# 前提介绍

**[Role & Goal]** 你现在是我的首席 AI 架构师和全栈工程师。我们将共同构建一个前沿的多模态生成式 AI 项目：**IP Meme 动画与多维资产生成引擎**。请仔细阅读以下项目背景、核心要求与开发原则。在理解全部内容后，请不要急于写业务代码，而是先输出项目的目录结构和基础环境配置建议。

**[Project Vision]** 系统接收一个常见的 IP 人物图像（通常是卡通动画人物），生成以该 IP 为主题的、带有夸张形变（Squash and Stretch）和 Meme 风格的短动画表情包。同时，系统需要具备多模态理解能力，从生成的 2D 结果中提取 3D 模型（用于空间一致性）和 SVG 矢量图（用于后期可编辑性与风格迁移）。

**[Prioritized Requirements]** **优先级 1（核心诉求）：夸张形变与 Meme 风格的呈现**

- 生成结果绝不能是僵硬的“微表情”变化，必须具备卡通动画中经典的夸张物理形变（如眼球突出、下巴拉长等 Meme 视觉效果）。
- 要求在工作流中引入成熟的前沿动画生成或形变控制框架（如 ToonCrafter、LivePortrait 或基于特定运动轨迹的 ControlNet）。

**优先级 2（高阶可控性）：3D 空间还原**

- 需要从单张/多张 2D Meme 关键帧中，推导出对应的 3D Mesh（`.obj` 或 `.glb`）。
- 要求引入极速单图生 3D 模型（如 TripoSR 或 LRM 相关开源方案），为后续跨视角渲染打基础。

**优先级 3（工业级编辑）：SVG 矢量化解析**

- 将光栅化的 2D 像素表情包转换为具备层级结构的 SVG 矢量图。
- 要求引入基于语义分割的矢量化方案（如 Segment Anything 结合图层化贝塞尔曲线拟合，或类似 VectorFusion/LIVE 的矢量模型）。

**优先级 4（基石）：IP 角色特征一致性**

- 引入免微调或极轻量微调的角色一致性方案（如 IP-Adapter 系列），确保夸张形变发生时，角色核心特征不崩坏。

**[Tech Stack & Environment]**

- **后端语言**：Python 3.10+
- **核心框架**：PyTorch, Diffusers, Hugging Face Transformers
- **API 调度**：FastAPI (用于解耦各个模块并提供接口)
- **其他核心库**：OpenCV, trimesh (用于 3D 处理), svgwrite/pypotrace (用于 SVG 处理)

**[Development Principles for Claude Code]**

1. **模块化解耦**：将 IP 提取、Meme 动画生成、3D 还原、SVG 生成拆分为独立的类和微服务，严格禁止写成一个庞大的单体脚本。
2. **显存（VRAM）管理至上**：由于涉及多个前沿大模型，必须在代码中实现显存的动态加载与卸载（Offloading to CPU），防止 OOM (Out of Memory)。
3. **渐进式开发**：遵循“设计 -> 确认 -> 编码 -> 测试”的循环。一次只实现一个模块，验证成功后再进行下一步串联。
4. **前沿导向**：在具体实现时，若发现有最新开源的 SOTA 模型比我提议的更好，请主动提出并解释替换理由。

---
  关于模块间通信方式的选择                                                           
                       
  方案 A：FastAPI 微服务（进程隔离）
  每个模块独立进程，通过 HTTP 调用。优点是隔离性强、可独立扩缩容；缺点是模型在进程间
  无法共享显存，跨进程传输大张量（图像/mesh）有序列化开销。

  方案 B：单进程 Pipeline + FastAPI 网关（推荐）
  所有模型在同一进程内，由一个统一的 ModelRegistry 管理加载/卸载，FastAPI
  只作为入口网关。优点是显存可统一调度（这对你的 VRAM
  管理优先级至关重要）；缺点是单点故障。

  鉴于你的优先级 2（VRAM 管理至上），我强烈建议方案 B。多个大模型（LivePortrait +
  TripoSR + SAM）同时跑在不同进程里，显存会失控。
